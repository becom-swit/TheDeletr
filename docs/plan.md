# TheDeletr – Implementation Plan

Based on [idea.md](idea.md). Console app that deletes files older than a given date from a root folder (local or network share), with exclusions, dry run, confirmation, progress and audit logging.

## Tech Stack

| Concern | Choice |
|---|---|
| Runtime | .NET 10 console app (C#, nullable enabled) |
| CLI parsing / help | `System.CommandLine` |
| TUI (list, prompt, progress, report) | `Spectre.Console` |
| Audit logging | `Serilog` + `Serilog.Sinks.File` |
| Recycle bin deletion | `Microsoft.VisualBasic.FileIO.FileSystem` (part of .NET, Windows only) |
| Tests | xUnit + `Microsoft.NET.Test.Sdk` |

## Command Line

```
TheDeletr <root> -d <date> [options]
```

| Option | Alias | Required | Description |
|---|---|---|---|
| `<root>` | positional | yes | Root folder (local path or UNC share), must exist |
| `--deletion` | `-d` | yes | Cutoff date. Files with `LastWriteTime <= date` are candidates |
| `--dryRun` | `-dr` | no | List candidates only, then exit |
| `--excluded` | `-e` | no | Comma/semicolon separated exclusion patterns |
| `--excludedFile` | `-ef` | no | File with patterns separated by newline, comma or semicolon |
| `--yes` | `-y` | no | Delete without confirmation |
| `--bin` | `-b` | no | Move to recycle bin instead of permanent delete |
| `--verbose` | `-v` | no | Suppress the per-file candidate list (only count is shown) |
| `--logFolder` | `-l` | no | Folder for audit log files (default: `logs` next to the executable) |
| `--help` | `-h`, `-?` | no | Help (generated by System.CommandLine) |

## Exclusion Matching

Applied to **both folders and files**. Patterns from `-e` and `-ef` are merged, trimmed, empty entries removed; matching is case-insensitive.

| Pattern | Meaning |
|---|---|
| `C:\data\keep` / `\\server\share\keep` | Full qualified path – exact match of the full path |
| `keep` | Name – exact match of the folder/file name |
| `keep*` | Name starts with `keep` |
| `*keep` | Name ends with `keep` |
| `*keep*` | Name contains `keep` |
| `sub\keep` | Path relative to the root folder |

`*` wildcards are also supported inside path patterns (e.g. `sub\*\cache`).

- Excluded **folder** → whole subtree is skipped (not traversed).
- Excluded **file** → only that file is skipped.
- Junctions / symlinked folders are never followed.

## Program Flow

1. Parse and validate arguments (root exists, date valid, exclusion file exists).
2. Initialize audit log; log run start with all parameters (user, machine, root, date, flags, exclusions).
3. Scan root recursively (manual directory walk so excluded folders are never entered); collect files with `LastWriteTime <= cutoff`. Show a Spectre status spinner while scanning.
4. Print candidates, one per line, unless `-v` is set. Always print total count and total size.
5. If `--dryRun` → log summary, exit `0`.
6. If no `-y` → Spectre confirm prompt. "No" → log "aborted by user", exit `0`.
7. Delete with a Spectre progress bar (permanent or recycle bin).
8. Remove folders that became empty (see Decisions).
9. Print report: `X files deleted in <duration>` (+ failed count and removed folders if any).
   - `< 60s` → `ss` seconds, `< 60min` → `mm:ss`, otherwise `hh:mm:ss`.
10. Log final summary, flush log.

## Audit Logging (Serilog)

- Sink: rolling file, one file per day: `<logFolder>/TheDeletr-YYYYMMDD.log`, retention 90 files.
- Logged regardless of `-v` (verbose only affects console output).
- Entries:
  - Run start: timestamp, user (`DOMAIN\user`), machine, all parameters.
  - Every candidate found (Debug/Information) incl. last modified and size.
  - Every deleted file (Information) with mode (permanent/bin).
  - Every failure (Warning/Error) with exception message.
  - Inaccessible folders during scan (Warning).
  - Dry run / user abort / final summary (counts, bytes, duration).
- Console output stays on Spectre.Console; Serilog writes to the file only.

## Error Handling

- Access denied / path too long / share disconnect during scan → warning, folder skipped, scan continues.
- Delete failure (locked, read-only, permission) → error logged, counted as failed, deletion continues.
- Files changed or removed between scan and deletion (e.g. while waiting for confirmation) → skipped and logged.
- Ctrl+C → cancels; no empty-folder cleanup after cancel.
- Exit codes: `0` success, `1` invalid arguments, `2` completed with failures, `3` cancelled.
- Read-only files are **not** force-deleted; they count as failed.

## Notes / Risks

- Recycle bin does **not** exist for network shares: with `-b` on a UNC path, Windows deletes permanently. The app will warn about this (and log it) before confirmation.
- `--bin` is Windows only; on other OS the option is rejected.
- Date parsing uses current culture plus ISO `yyyy-MM-dd`; time portion optional (date only = `00:00:00` of that day).

## Decisions

1. Cutoff date without time → `00:00:00` of that day (files with `LastWriteTime <= yyyy-MM-dd 00:00:00` are candidates).
2. Read-only files are **not** force-deleted; they are reported and counted as failed.
3. Folders that become empty because of the deletion are removed afterwards (bottom-up). The root folder, excluded folders and folders that were already empty before the run are never removed. Removed folders are logged and shown in the report. With `--bin` the folders are moved to the recycle bin too.
4. Audit logs: `logs` folder next to the exe, retention 90 days.

## Implementation Steps (all done)

1. **Scaffold** – create `src/Thedeletr` console project (net10.0) and `tests/Thedeletr.Tests` xUnit project, add both to `thedeletr.slnx`, add NuGet packages.
2. **Options & CLI** – `DeletionOptions`, `CommandBuilder` with all options/aliases, validation, help text.
3. **Exclusions** – `ExclusionParser` (string + file, separators `,` `;` newline) and `ExclusionMatcher` (path / name / prefix / suffix / contains). Unit tests.
4. **Scanner** – `CandidateScanner` recursive walk with exclusions, date filter, error tolerance. Unit tests with temp directories and `File.SetLastWriteTime`.
5. **Duration formatting** – `DurationFormatter` + tests for boundaries (59s, 60s, 3599s, 3600s).
6. **Deleter** – `FileDeleter` with permanent / recycle-bin strategy, progress callback, result (deleted, failed, bytes), read-only files → failed, removal of folders emptied by the run. Tests for empty-folder cleanup.
7. **Audit log** – `AuditLog` Serilog setup, log calls in scan/delete/flow.
8. **UI** – `ConsoleUi`: candidate list, scanning spinner, confirm prompt, progress bar, final report, network-share bin warning.
9. **Wire up** – `Program.cs` orchestrating the flow and exit codes.
10. **Verify** – build, run tests, manual run against a temp folder (dry run, exclusions, `-y`, `-b`).
11. **Docs** – `README.md` with usage examples.
